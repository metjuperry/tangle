# Decisions

| Date | Question | Answer |
| --- | --- | --- |
| 2026-10-10 | There is no Git repository or remote. | Initialize a local repository, preserve the supplied docs on `main`, and use `milestone/m0` and `milestone/m1`. Do not create a remote repository without a destination. PR creation and remote CI are blocked until a remote is supplied. |
| 2026-10-10 | How does a browser supply the local development key? | A same-origin login form exchanges the key for an HttpOnly, SameSite=Strict cookie. API clients may also use a Bearer key. Check Host and Origin before authentication; never put the key in a URL or browser storage. Only the login shell and liveness probe are public. |
| 2026-10-10 | The schema omits watched organizations, reviewer identity and commit authors needed by later rules. | Add an `organization` settings table, `pr_review_request` cache table, and keep typed event details as JSON in `pr_event.detail`. Include the documented `ai_call` log. No facts or AI behavior is implemented before its milestone. |
| 2026-10-10 | The design mentions config.json, while M1 requires settings in SQLite. | Watched scope settings live in SQLite per M1; tokens and runtime settings come from environment variables or user-secrets. Defaults start empty until explicitly configured. The `involves:@me` scope includes authored and review-requested PRs pending checkpoint A. |
| 2026-10-10 | Can M0 seed demo data when full demo mode is M10? | M0 browser tests use a separate temporary database and development key. Do not implement demo mode or touch the user's working database. |
| 2026-10-10 | NuGet reports vulnerable native SQLite bundled by Microsoft.Data.Sqlite. | Keep Microsoft.Data.Sqlite and explicitly pin its SQLitePCLRaw bundle to patched 2.1.13. Do not suppress the vulnerability warning. |
| 2026-10-10 | Personal repositories need a different GitHub search qualifier from organizations. | Store owner kind as org/user through forward migration 0002. Use org: for organizations, user: for personal accounts, repo: for individually watched repos. Defaults stay empty; TALXIS and metjuperry are only used in the isolated validation database. |
| 2026-10-10 | The example GraphQL query truncates files, threads, reviewers and timeline events. | Follow nested connection cursors, including backwards timeline pagination, so cache data is complete. Reject searches over GitHub's 1,000-result ceiling rather than quietly claiming completeness. |
| 2026-10-10 | How to expose sync progress before SSE arrives in M3? | M1 POST /api/sync waits for completion, reports counts and errors, and prevents concurrent syncs. SSE progress and open-board automatic sync remain M3 work. |
| 2026-10-10 | Real empty incremental searches still cost 53 points each with the nested query. | Use ChangedPrs.graphql as a cheap incremental probe, and run the full Prs.graphql only for nonempty pages. Log every call and include nested calls in the result metrics. This retains full data without paying the expensive query cost for unchanged scopes. |
| 2026-10-10 | What does disabling a watched owner mean for its discovered repos? | Disabling an owner pauses and hides all its repos; individual repo scopes run only for owners absent from the owner list. Repo switches can narrow an enabled owner. Confirm this precedence at checkpoint A. |
| 2026-10-10 | Re-enabling a repo can miss changes older than its owner's cursor. | Reset sync cursors when watched settings change; the next sync performs a full open search. This modifies only disposable sync metadata, never cached PRs or user-authored data. Saving identical settings keeps the incremental cursor. |
| 2026-10-10 | Is checkpoint A approved? | Metju tested the checkpoint, said it looks good, and explicitly requested continued implementation. Proceed with M2 on milestone/m2, stop at B. No remote destination was provided; do not publish or merge. |
| 2026-10-10 | Size bucket cutoffs are unspecified. | Reversible initial cutoffs by additions + deletions: XS <=10, S <=100, M <=500, L <=1000, XL >1000. Confirm at B. |
| 2026-10-10 | How are unknown behind-base counts represented? | Keep behind_by NULL because the named query does not supply it; never claim zero. Raise at B before adding compare queries. |
| 2026-10-10 | Which comments count toward idle and open asks? | Include last review-thread comments in human activity. Null actors and configured bots cannot be the last human actor; unresolved asks need an identified non-bot actor other than the viewer. Treat FAILURE/ERROR rollups as failing; missing/pending checks are not green. Confirm at B. |
| 2026-10-10 | How are title identifiers and 14-day batches interpreted? | Normalize backtick identifiers, hyphen/underscore/dot/slash identifiers and numbers; preserve ordinary words. Group open PRs by repo, author and normalized title, choose earliest inclusive 14-day windows with at least five members (no chaining beyond 14 days). Confirm at B. |
| 2026-10-10 | How are stale facts refreshed without background work? | Recompute cached facts, batches and rules at startup and each successful scope sync, even if no PR changed, and when bot settings change. Use one cache transaction per pass. Rule priority for a pair is explicit, then stack, then file overlap; preserve user decisions, labels, cuts and non-rule rows. |
| 2026-10-10 | Real scaffold titles vary by template name before "scaffold applier". | Normalize only the exact "feat: <template> scaffold applier for <identifier>" family to a shared pattern. Recorded public metadata contains 33 appliers in an inclusive 14-day window, plus two unrelated search hits that must not join. Confirm this narrow family rule at B. |
| 2026-10-10 | Is checkpoint B approved? | Metju confirmed the rules work and requested the next phase. Proceed with M3 and stop at C. Existing thresholds remain unchanged. The remote is now metjuperry/tangle; no merge authorization was given. |
| 2026-10-10 | Should M3 mimic the screenshot's AI actions and editing buttons? | No. Match its visual hierarchy but show computed whose-turn facts, not invented AI verdicts. Untangle is visibly unavailable until M6; strings/card positions are read-only until M4. Card descriptions are plain escaped text, not AI intent. |
| 2026-10-10 | How do batches pick a pin and expose individual cards? | The representative is your-turn first, then nobody, then others, sorting by idle within each. The batch back lists all members for selection. Internal batch strings are omitted from the graph but retained as text on individual card backs. Confirm at C. |
| 2026-10-10 | How is the independent remote initial commit preserved? | Merge the README-only remote master history into the oldest milestone branch without rewriting commits, propagate that ancestry through the stack and publish one PR per milestone. Leave every PR unmerged pending explicit merge authorization. |
| 2026-10-10 | How is M3 tested without shipping early demo mode? | A test-project Kestrel host seeds a fresh fixture SQLite store and replaces GitHub with a fake. It is not a production Host feature or --demo implementation. SSE tests use the real authenticated endpoint, including a sync from an independent API client. |
| 2026-10-10 | Has remote publication been restored? | Published M0–M3 as stacked PRs #1–#4 in metjuperry/tangle after the remote was added. All remain unmerged. Actions is enabled, but GitHub initially reports no runs/checks or registered workflow; remote green CI remains unverified and must not be claimed. |
| 2026-10-10 | Checkpoint C review: red tags cannot be clicked, dimming seems ineffective. | Reproduced tag interception by the React Flow node layer; raise the edge-label layer and add centered check-mark/tooltip/legend guidance. Dimming already works for other-authored cards; disable it with an explicit all-mine label when there are none. It does not dim your own PRs waiting on other reviewers. |
